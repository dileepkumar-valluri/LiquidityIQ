# LiquidityIQ — Source Manifest

## 1. Data Sources

| Source | Data Used | Source Type |
|---|---|---|
| `scripts/generate_data.py` | Legal entities, bank accounts, ledger entries, receivables, payables, FX rates, scenarios, forecast runs and cash-flow forecasts | Generated synthetic data |
| Fixed random seed (`20261022`) | Deterministic random generator configuration | Generator configuration |
| `backend/app/models/` | Entity structures, primary keys, foreign keys and constraints | Project implementation |
| `backend/app/services/forecasting.py` | Daily cash positions, FX conversion and scenario calculations | Project implementation |
| `backend/app/services/actual_vs_forecast.py` | Forecast-to-actual comparison | Project implementation |
| `backend/app/services/edge_cases.py` | Five labelled financial data-quality edge cases | Synthetic test fixtures |
| `backend/app/services/validation.py` | Dataset integrity and business-rule validation | Project implementation |

## 2. External Data

The datasets are synthetic. No confidential company financial records or real customer banking records are included.

Generated exchange rates are synthetic and must not be treated as live market rates.

## 3. Dataset Configurations

The generator supports two configurations.

### Starter

- Legal entities: 3
- Bank accounts: 15
- Ledger entries: 1,000
- Receivables: 200
- Payables: 200
- Forecast source items: 400
- Forecast runs: 3
- Cash-flow forecast records: 1,200

### Baseline

- Random seed: `20261022`
- Legal entities: 30
- Bank accounts: 150
- Ledger entries: 100,000
- Receivables: 10,000
- Payables: 10,000
- Distinct forecast source items: 20,000
- Forecast runs: 3
- Cash-flow forecast records: 60,000
- Currency rates: 80
- Liquidity scenarios: 3

The baseline contains 20,000 distinct source items represented in three forecast runs, producing 60,000 forecast records.

## 4. Edge-Case Fixtures

Five labelled edge-case types are maintained separately from the clean generated baseline:

1. Opening balance reconciliation mismatch.
2. Missing foreign-exchange rate.
3. Duplicate cash flow.
4. Actual transaction posted after forecast cutoff.
5. Currency aggregation without conversion.

The fixtures are generated by `backend/app/services/edge_cases.py` and evaluated by `backend/app/services/edge_case_validation.py`.

The five anomaly types have been detected successfully in the separate fixture dataset. They have not been injected into the clean baseline dataset.

Ground-truth labels are stored separately from baseline financial input records.

## 5. Validation Evidence

- Baseline validation: 33 checks passed, 0 failures.
- Automated test suite: 36 tests passed against the starter dataset.
- Edge-case fixture detection: 5 of 5 cases detected.
- Baseline negative closing-balance warnings: 56 accounts.

Negative closing balances are retained as liquidity warnings rather than silently removed.

## 6. Limitations

- Synthetic exchange rates do not represent actual market prices.
- The baseline has been generated and exported, but full repeated-run checksum reproducibility has not been independently verified.
- The automated test suite is not a complete baseline-scale test run.
- Edge-case fixtures are separate from the clean baseline.
- Daily cash positions are calculated by the forecasting service.
